# Mixed eligible bulk renewal admission

The central API qualification runner executes six mandatory `bulk-eligible-api` scenarios against a disposable API/PostgreSQL fixture with OpenSSL. Genuine public certificate imports have complete linked renewal profiles and agent-local admission metadata seeded as explicit prerequisites. No CA or native agent executes these jobs.

The actual public bulk endpoint must report independent eligible, unprofiled and unknown-certificate outcomes. Dry-run admits eligible items without jobs. Three pending-approval public issuance jobs reserve the same CA bucket; bulk renewal then reserves its remaining two slots and refuses the third eligible item at capacity. Replaying the request preserves both successful job IDs without consuming another slot. Public requester rejection frees one slot, allowing the previously refused item on replay. A public profile edit cannot alter an already queued bulk payload.

Independent SQL reads check persisted jobs, statuses, capacity and payloads; fixture cleanup is mandatory. Focused local execution passed all six scenarios and independent strict report verification. Hosted execution, actual CA renewal, native effects and scheduler recovery remain separate qualification requirements.
