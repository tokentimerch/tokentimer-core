# Downstream edition qualification

An edition that composes Core must qualify its own API policies and exact Core composition. Core's release matrix verifies this repository's candidate; it does not import reports from another repository or imply that an edition has adopted new Core features.

Downstream qualification should record the edition candidate, exact Core commit and contract versions, source digests, mandatory scenario inventory, measured runtime and owned resource cleanup. Reports must distinguish fixture entitlement records from actual billing or licensing transitions and supporting API assertions from native certificate execution.

The catalog retains requirements for hosted plan, quota, frozen-workspace and role boundaries, license and compliance policy, and full certificate promotion and renewal journeys. These are extension requirements for downstream qualification, not executable tests or verified results supplied by this checkout.

Each deployment must verify public issuance, observation, profile derivation and scheduler renewal against its actual composed API and native agent. Browser behavior, Windows services, package upgrades and entitlement transitions require their own measured execution. A report against an older Core pin cannot qualify a newer candidate or features absent from that composition.
