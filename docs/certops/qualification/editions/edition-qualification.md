# Edition qualification stays tied to its composition

Cloud and Enterprise have their own candidate SHA, API policy and pinned Core composition. Their reports are verified in their owning edition, separately from the current Core release matrix. Repository-prefixed implementation paths in the scenario catalog identify those external sources; they are not files in the Core checkout.

Cloud's `scripts/cloud-certops-qualification.js` and `tests/e2e/cloud-certops-required.json` require24 real SaaS API/PostgreSQL cases. Focused local execution passed current-source policy, quota, frozen-workspace, role and machine continuation/security/upgrade/downgrade boundaries. It preserved Core0.17.3 at `b6ad7fc3d38db35b4c41a2c6137b0c39afc72158`; the local Node24.18 execution remains a worktree baseline rather than hosted Node22/release evidence. Entitlement transitions are explicit prerequisite database records, not payment-provider transitions. The separate Cloud native ACME source requires nine milestones across Certbot/acme.sh and Pro/Team, using actual SaaS public issuance and two production scheduler renewal generations with concurrent selection and the pinned real agent and trusted served TLS. That native workflow has not run.

Enterprise's `tests/integration/certops-qualification.json` requires48 cases covering entitlement/compliance/audit/trust RBAC/job admission. Focused execution passed twice against the actual source-built API/PostgreSQL runtime, with independent489-runtime-source hashes, image identity, ephemeral license verification and owned cleanup. It preserves Core0.17.3 at `155fe990c23f35fd9bb0a65897e985af9fb849d2`; hosted qualification and native certificate execution remain pending.

Both pins precede newer AD CS work. An edition must advance its composition through its normal sync process before new Core features can be attributed to that edition. These results cannot satisfy a current-Core-SHA release slot or declare all certificate capabilities qualified. Billing payment flows, native Windows/Azure, edition browser journeys and complete packaged upgrade behavior require their own measured reports.
