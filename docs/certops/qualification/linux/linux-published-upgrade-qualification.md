# Published Linux archive upgrade qualification

The trusted manual `certops-linux-published-upgrade.yml` workflow requires Ubuntu 22.04 and 24.04 independently. It installs the actual public `v0.17.2` archive first, then upgrades the already registered non-root systemd service with a candidate archive built by the repository's real `pack-release.js`. The candidate must have a strictly later package version. Current source and helper binaries are never injected into the historical package.

The public predecessor is asset `612562598`, `tokentimer-agent-0.17.2.tgz`, 410054 bytes, SHA-256 `c602fe36825c74d423c2c9b89680df3b1ac76542f71804de14dc5e2ec5aa85bf`, from the [official v0.17.2 release](https://github.com/tokentimerch/tokentimer-core/releases/tag/v0.17.2). The workflow validates official release metadata, the pinned digest, the published checksum file and the archive's own version/runtime prerequisites. It rejects unsafe paths, links, special entries and duplicate archive members before extracting into a fresh run-owned directory. This is content/hash provenance, not a publisher code-signature qualification.

The official candidate pack step builds its required Windows service-host payload with the existing Go module/version setup, although this workflow executes only Linux JavaScript. It neither downloads a second candidate package nor pretends the candidate-built archive is a previously published asset. Both package versions and archive digests accompany the strict report, which also binds current orchestration, installer and packer sources. Every regular package file is measured from a separate extraction of the verified archive. Extracted inputs and installed application trees must match those names, sizes and digests exactly; only the installer's documented root `node_modules` exclusion applies to installed trees. Missing, substituted, additional or linked runtime files fail.

Five mandatory scenarios require the historical package to execute a real signed no-op job, upgrade while preserving exact operator config and credential bytes/private permissions, reuse its existing API registration without consuming a spare bootstrap token, execute another job with the candidate, and restore the original owned configuration. Production job creation creates the fixture no-ops; the installed historical and candidate agents use the actual HTTP claim, evidence and result routes. Persisted completed-job/evidence history and the still-valid historical replay-cache entry must survive unchanged. Exceeding that actual signed replay window fails the test rather than inventing older nonce state.

The full extracted and installed regular-file inventories must match content hashes derived from the verified archives before and after upgrade, including signing, platform and vendored runtime files; only the installer’s root `node_modules` exclusion is accepted. Actual systemd PIDs, non-root identity, authenticated heartbeats and a fresh restart after bootstrap-file removal provide independent process/authority checks. No-op history establishes agent compatibility and durable state preservation; it does not prove certificate renewal, private-key custody or a database schema upgrade.

Only `linux-systemd-published-upgrade.json` is uploaded from this workflow. Supporting base-journey reports are not uploaded again, avoiding duplicate release-environment evidence. The existing receipt-bound systemd teardown runs independently on failure, followed by destruction of the disposable API/PostgreSQL stack. The fixture restores only its own config, refuses unexpected bootstrap-file deletion, and revokes its unused token. Automatic version rollback is not a supported installer contract and is not claimed.

The genuine predecessor archive and official metadata passed read-only inspection during implementation. Portable provenance/oracle tests, source checks and Actions schema validation passed. Neither the historical installer, candidate pack/build nor native systemd upgrade has executed during implementation; both hosted environment slots remain unqualified until their actual runs pass.
