# Public bulk renewal with two actual native ACME completions

This source is limited to the existing disposable Ubuntu certbot/no-EAB foreground-agent journey. It requires its genuine healthy serving certificate, the owned local Pebble CA and DNS provider, and the actual registered production agent. No certificate, profile, job, claim, expiry or result is seeded.

After the existing background-worker and key-reuse controls, and before retirement, the fixture independently requires the original worker to be stopped, waited and drained. It publicly issues two additional certificates to separate owned filesystem targets. The issue service allocates distinct managed-certificate identities from separate request keys and target paths; the fixture independently requires distinct IDs, paths and stored profiles. Both fresh profiles must already require key rotation. Separate dynamic TLS listeners serve both real deployed pairs. The original serving certificate, private key and profile remain unchanged.

One public bulk request contains both eligible identities and an independently absent UUID. The response must contain two exact jobs and one not-found outcome. Replaying the same request must return those same jobs. Actual database allocation for the request prefix must contain exactly those two subjects and jobs. Both current claims must belong to the original registered agent and complete on their first actual attempt. Each independently parsed issued leaf must change serial, fingerprint and SPKI, match its local private key and inventory, advance expiry, and be served through independently CA-root-trusted hostname-checked TLS. Verification evidence must bind the current claim and actual leaf fingerprint, while stored profiles remain unchanged and real DNS records are cleaned.

Both additional certificates' exact open management periods are then stopped through the supported public API. This prevents later scheduling from accidentally renewing these extra fixtures. It does not change either stored key policy or claim to qualify automatic bulk scheduling.

A resource is registered before its listener or public mutations. All accepted and probe sockets and the retained listener must close before the exact owned guard can be released. Unknown admission, native completion or cleanup preserves the root and public ownership state through the parent cleanup barrier. Reports contain public IDs and cryptographic certificate facts only. Private keys remain in the original restricted owned agent context.

Pure parser, response-binding and proof-adversary tests do not qualify native execution. The protected native workflow remains unexecuted. This case covers mixed public admission and two successful native items, not every provider fault or every bulk failure combination.

The existing dedicated native-console and lifecycle wrappers reuse this complete base journey and hash its bulk dependencies. Their separate host reports retain their UI scope; they cannot substitute for the base bulk stack report. Collection binds the base stack report to `certops-real-acme.yml`. No workflow or runner is added for this case.

The base certbot/no-EAB native test has a 30-minute limit and its runner a 32-minute limit, retaining a 2-minute outer margin. Other client/account test limits remain 20/22 minutes. Existing regular and browser workflow limits remain 45/55 minutes. These are configured failure bounds; actual native duration has not been measured in this implementation session.
