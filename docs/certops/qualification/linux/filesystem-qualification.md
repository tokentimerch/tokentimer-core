# Native certificate filesystem qualification

`certops-filesystem-qualification.yml` is a trusted-main manual workflow for Ubuntu 22.04/24.04 and Windows Server 2022/2025. It runs the production filesystem deployment, policy, and pre-deploy verification modules against real temporary directories, native OpenSSL, POSIX permissions or Windows ACLs, and a real directory symlink or junction. No filesystem or subprocess implementations are mocked.

Seven mandatory cases prove first certificate/key/chain deployment, fresh-process idempotent replay, certificate/key rotation with byte-identical predecessor backups, refusal of an actual link escaping the allowed root, input/policy refusal without mutation, explicit backup finalization, and cleanup. Fresh CA-signed leaves are independently parsed, matched to the deployed local key, and verified by OpenSSL against the deployed chain and requested hostname. Private bytes and hashes of private artifacts are never written to the uploaded report.

Live and backup key files must have POSIX mode `0600`, or protected Windows ACLs allowing only the actual current user, SYSTEM, and Administrators. Unexpected allow trustees fail the independent ACL oracle. A mismatched key fails the production pre-deploy validator. Missing explicit key destinations, private-key bytes supplied as a certificate, and paths outside the local allowlist must leave the existing deployment unchanged. The containment case checks the actual escaped directory and a sentinel before and after refusal.

The executor intentionally receives the production local policy callback and retains fixture staging keys so replay can independently test real idempotence. The report classifies this as native executor coverage. It does not qualify signed dispatch, installed-service identity, a server reload, TLS cutover, multi-target rollback, process interruption during rename, or disk failure. Those require their own journeys. The native workflow has not been run during implementation; full CI execution remains pending.

Cleanup checks the resolved absolute temporary-directory parent and generated fixture prefixes before recursive deletion, attempts both owned directories even after one failure, and verifies their absence. It removes the link itself rather than traversing it. Missing prerequisites, skipped mandatory cases, failures, and incomplete cleanup fail strict qualification. Only sanitized named reports are uploaded; private keys, replay inputs, native command output, and backup files are excluded.
