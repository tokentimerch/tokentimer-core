# Certificate execution across operator signing-key rotation

The manual workflow `.github/workflows/certops-acme-certificate-signing.yml` is `workflow_dispatch` only. It starts a separate disposable Ubuntu certbot/no-EAB API, PostgreSQL and Pebble stack, and it refuses a repository `.env` or an already running shared API database container. It never rotates a shared database.

An unarmed predecessor issuance creates one owned certificate. The in-flight public renewal is held at the owned native command barrier only after the production agent has verified that renewal's original signed claim. A read-only observer records the job and signing-key ids from the unmodified version-two envelope. The observer does not verify the signature. Current-claim state and the consumed dispatch nonce establish production admission. Operator rotation then begins, receives the real heartbeat pin acknowledgement, and completes without force before that original certificate command is released.

The original renewal and a subsequent new-key signed renewal must both produce CA-issued leaves, matching local keys, independently trusted served TLS, current-claim verification evidence and a single attempt. The existing execution key-rotation policy is recorded and must match the observed key change. Configuration and credentials stay unchanged. The signing pin changes to the authenticated replacement. Original native command drainage, exact protocol-file identities and sticky cleanup authority protect database and private state on every uncertain failure.

The native producer `scripts/certops-acme-certificate-signing.js`, its separate invocation, the strict public report projection, and the mandatory cell `linux-native-certificate-signing-rotation` are implemented in this source. They are not registered in the scenario catalog, qualification suites, release matrix, release collector, CI selection, qualification README, or skip inventory. No native signing rotation, agent, CA, provider, browser, or workflow execution has been performed. Native execution remains pending. This document does not claim that the native run happened. The separate noop pin-adoption suite remains limited to operator begin, incomplete-fleet refusal, heartbeat acknowledgements, completion and restart.
