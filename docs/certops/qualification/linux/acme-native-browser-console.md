# Browser console for an actual Linux ACME agent job

This source adds a read-only dashboard actor for a separate Ubuntu 24.04,
certbot, no-EAB qualification lane. Its dedicated manual workflow and strict
runner are connected to the real native journey and a distinct strict release
cell. The real production agent CLI runs in the foreground from the candidate
checkout with an owned configuration; this lane does not qualify OS service
installation or a published installer. No native browser, ACME, or agent execution has been
performed for this case. The existing protocol-level browser console cases
continue to cover authorization withdrawal and lifecycle edges separately.

The actor starts the repository-pinned Chromium through a retained
BrowserServer, authenticates a real public account, and then arms the existing
owned external command wrapper. The caller must admit the real public issue
job immediately afterward. The wrapper pauses before launching certbot; the
agent has already verified the signed claim and persisted its genuine starting
line. No synthetic logs, browser network intercepts, CA responses, or production
test hooks are involved.

`observeAndRelease` binds the actual job, certificate, claim and agent database
identities; independently reads the owned wrapper's Linux parent, process group,
start ticks and command arguments; and opens the dashboard's exact filtered
job. Both the real log response and the rendered starting line must be visible
while the job is nonterminal. Only then may the exact original arm be removed.
The actual native client continues against the qualification CA.

After the caller independently verifies real issuance and trusted consumer TLS,
`finish` requires the same job and claim to have succeeded, its genuine
completion line to appear in the dashboard, and its persisted stream to be
final with no gap or dropped lines. The actual database log count must match
the stream count. Claim-bound verification evidence and the managed certificate
fingerprint must agree with the caller's trusted TLS observation. All browser
CertOps writes must remain zero.

The public proof contains only UUIDs, public certificate and curated-line
hashes, bounded counts and closed observation flags. It contains no raw logs,
credentials, process arguments, browser endpoint, screenshots or traces. This
case does not test secret injection/redaction attacks or claim uninterrupted
log delivery across process interruption.

## Integration and cleanup contract

Create the actor with the native parent fixture's pool, workspace, registered
agent, real login identity, separately bound owned UI/API origins and
command-barrier directory. The dashboard and API may use different loopback
ports; actual list/log responses must originate at the independently supplied
API origin. CertOps writes are counted across every origin and workspace.
Register `ownedBrowserResources` before launching Chromium. Call `preparePage`,
admit the public job, call `observeAndRelease`, then complete the existing native
CA/TLS oracles and call `finish` with the independently observed fingerprint.
The initial browser session must be ready before the native wrapper's bounded
120-second wait starts.

The actor owns an exclusive local guard. Unknown browser launch outcomes,
changed arm/receipt identities, failed proof or incomplete process drainage
preserve it. Closing Chromium alone does not resolve an uncertain native job.
The parent must drain its retained browser and agent/client resources, then
call `assertCleanupSafe` **before** deleting API ownership or private fixture
files. It must preserve state when this assertion refuses. Only a successful
native completion plus actual retained-browser close releases the guard.

The dedicated workflow builds the real dashboard, installs the exact pinned
Playwright/browser and native client/CA, and runs on trusted `main` only. The
runner serves the built application through its retained in-process Vite HTTP
server while the real native journey runs asynchronously. It requires both
actual browser subcases, the closed native proof, and the full native ACME and
browser causal source inventory. Its own report is
`qualification-results/acme-native-console.json`; only that sanitized report is
uploaded. The existing five ACME lanes,
including Alpine, acquire no browser prerequisite or optional browser skip.
