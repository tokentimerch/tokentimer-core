# Native ARM64 desktop packaged service-host lifecycle

This separate manual Windows 11 ARM64 runner uses the actual freshly packed candidate service-host executable, with independent archive checksum and PE/digest checks. It requires native ARM64 Node and PowerShell, an elevated desktop token, and initial absence of the canonical TokenTimerAgent service and registry key. It never substitutes the renamed-source host used by the supporting installer smoke test.

The real LocalSystem SCM service launches the checked-in controlled mock child. Actual start, stop and fresh restart are observed through SCM and independent process creation, executable, command-line and SYSTEM identity observations. A real mock exit17 must trigger configured SCM recovery with a fresh host and child. A real exit86 must stop successfully without another start during at least five seconds measured monotonically. This proves packaged host behavior, not real-agent registration, API work, the installer CLI, Windows Server, IIS or certificate operations.

A private durable receipt records exact initially absent service ownership and captured process identities before destructive work. It also preserves original filesystem volume/inode/birth identities for the root, marker, candidate directories, host, mock, Node and receipt. Copying identical bytes or the same nonce into a replacement file/directory does not transfer ownership. The receipt retains its original inode through flushed in-place updates; a torn or unreadable receipt fails closed. The exact source-digest-bound read-only Node validator checks those actual identities before native service work and each receipt update. Cleanup validates unchanged candidate and child bytes, exact service/registry configuration and absence of captured descendants. Unexpected or still-live processes are preserved; cleanup never adopts or kills a numeric PID. The exact service and registry must be absent before the guarded temporary root is removed. A separate always-run cleanup invocation refuses while the original native owner remains live. Disposable hosted runner destruction remains the final interruption boundary.

Source and pure proof checks are implemented. Native ARM64 service execution is pending. This lane does not broaden the existing ARM64 CNG scope or the AMD64 Windows host suite.

The historical certops-windows-arm64-host.yml manual entry now fails immediately with links to the two explicit desktop workflows. The full windows-host suite contains AMD64-specific runtime oracles and remains unsupported on ARM64; its mandatory cases are neither skipped nor relabeled by these narrower lanes.
