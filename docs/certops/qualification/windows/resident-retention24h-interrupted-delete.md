# Real-day interruption between certificate and key deletion

The same disposable retention campaign keeps its genuine AD CS predecessor and
replacement on the original VM. The resident process measures a full monotonic
24 hours, observes custody before the actual production deadline, and then launches
the existing native deletion fault child inside a retained JobObject.

That child uses the original protected state and production collector. Its native
execution adapter delegates each command unchanged and exits with code 86 only
after the exact `certutil -delstore My <thumbprint>` succeeds, before key deletion
or durable ledger completion. The source checks the original configuration and
source digests, actual deadline and an owned launch gate; it never copies or ages
the ledger, injects a clock or fabricates an AD CS request.

After every contained native process is drained, independent observations require
that the predecessor certificate is absent across machine stores, its original
non-exportable key still signs for the recorded public leaf, and the incomplete
ledger has the same bytes and file identity. The replacement's native custody,
IIS SNI binding and trusted TLS remain unchanged. An ordinary production sweep
then reacquires the real lock using its default clock, removes the retained key
and completes the original ledger row. Final native checks precede proof release.

Unknown process drainage, changed ownership or incomplete recovery preserves the
campaign's receipt and protected state for independent owned Azure teardown.
Only bounded public facts are eligible for reporting; process receipts, raw native
output and configuration files remain private. Source and supporting pure/AST
checks do not qualify native execution. This case covers a genuine 24-hour window;
it does not qualify the 168-hour default window or 720-hour maximum, the installed six-hour sweep cadence,
or power-loss durability.
