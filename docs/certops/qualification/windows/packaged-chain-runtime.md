# Packaged chain helper runtime boundaries

The candidate archive contains the service-host and chain/store-query executables. The disposable Windows host fixture copies that actual extracted candidate into an owned path containing spaces, Unicode and literal brackets, verifies native helper digests independently against freshly built candidate bytes, then invokes the copied production resolver and metadata-only native survivor bridge. The random container selector creates no key. The real helper must return complete machine-store metadata and zero matches.

The protocol fault replaces only that owned copy of the chain executable with the actual candidate service-host executable. This is a structurally valid native PE with the wrong protocol, rather than another missing/truncated/wrong-architecture test. It receives only the metadata argv; a restricted PATH and explicit directory checks prove its deliberately invalid child command absent. Its configuration/log directory stays inside the owned runtime copy. No service is installed. The real production bridge must refuse it conservatively. Exact ChildProcess close precedes restoration, and original file ID, size and digest must match before a fresh positive native metadata query. Unresolved process or file ownership prevents parent cleanup.

The named host scenario is `windows-packaged-chain-runtime-protocol-refusal`, with closed `nativePackagedChainRuntime` evidence. Source and ordinary temporary-file/proof controls are implemented; native execution remains pending. This does not qualify ARM64 native execution, an installed-service helper replacement, externally authenticated signed release provenance or CRL/OCSP behavior.

CMC decoding is separately built from the same candidate source in the domain lab. Its resolver still searches `reference/adcs-cmc/dist`; CMC is not in the default candidate package's binary allowlist. The release capability manifest still keeps `adcs-enroll-v1` unqualified; the lab enables only its isolated qualification build. Release enablement of AD CS still requires that packaging boundary to be resolved. The Go signature verifier is a reference implementation used by protocol qualification; the agent's production signature verifier is JavaScript. Neither is promoted to a packaged CMC/native-verifier claim by this scenario. This limitation is distinct from historical published archives lacking service-host executables.
