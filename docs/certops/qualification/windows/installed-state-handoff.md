# Explicit installed Windows service state handoff

The agent has no dedicated re-register command. Its unmodified CLI starts the normal agent and registers only when the selected state has no credential. An existing credential takes precedence over a supplied bootstrap token. The installer preserves its state directory. This qualification therefore covers an explicit operator-directed change to a fresh protected state directory, rather than automatic in-place credential migration.

After the original installed agent has genuinely retired and SCM is stopped, the helper preserves the original state byte for byte. It copies only local keys, issuance receipts, retention ledger, trust receipts, completed job/enrollment journals, replay state and the signing pin into another run-owned protected directory. It rejects symbolic links and native Windows reparse entries before traversing them. It never copies the old credential, bootstrap environment, registration transaction, outbound queue or outbound sequence state. Machine CNG keys remain in their existing provider; no native key is exported.

A real authenticated public request creates each bootstrap token. Reusing the retired identity through the candidate CLI and independent public registration request fails without consuming its token. The old credential receives an actual HTTP 410. A fresh identity then registers through the byte-identical installed candidate CLI in the prepared state. A test-only launcher creates the unmodified CLI suspended, assigns it to a retained kill-on-close Windows Job Object, then resumes it. The parent verifies the actual launcher PID, creation time, parent, executable, SYSTEM identity and command token before releasing its start gate. Shutdown terminates that retained job and requires zero active members plus a closed-root handle and wrapper close receipt. Wrapper exit alone cannot release ownership. The harness drains that exact native process job before handing the same state to SCM. The original service executable/account remain fixed; the running replacement process must be SYSTEM and subsequently send a fresh authenticated heartbeat after an independent database marker. This replacement runs with execution and discovery disabled to isolate identity handoff and custody preservation.

Independent observations require identical original state, copied custody/journal bytes and signing pin, machine CNG metadata, exact IIS/HTTP.sys binding and trusted served certificate. Predecessor jobs must remain unchanged. No bootstrap token is persisted in the service registry. The replacement is retired through the public API, its service stops, and the exact original registry value is restored. Only then may owned replacement state be removed. The unused conflict bootstrap is explicitly revoked.

The parent must register the helper's ownership resource before any process/registry mutation, retry its close method during cleanup, and preserve fixture state while a registration child or registry ownership receipt remains. Service path/account or registry replacement by another actor causes cleanup to fail closed. Credentials and registry receipts remain inside protected fixture state and never enter reports.

Offline tests cover the strict bounded proof, the copy allowlist and link refusal without starting services or touching native certificates. Actual SCM/CNG/IIS qualification is pending on the protected installed-agent Windows lanes. This scope does not transfer old AD CS jobs to a new identity, prove automatic migration, or qualify a replacement certificate issuance.
