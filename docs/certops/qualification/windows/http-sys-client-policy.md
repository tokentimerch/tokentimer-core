# HTTP.sys client-certificate policy preservation

The disposable Windows host fixture observes the native HTTP.sys IP-binding registry independently of the production decoder. Two owned configurations set client-certificate revocation, cached-only revocation and usage checking to explicit combinations, with nonzero freshness and retrieval timers. Expected raw check-mode bits are NO_REVOCATION=1, CACHED_CLIENT_CERT_ONLY=2, FRESHNESS_TIME=4 and NO_USAGE_CHECK=0x10000.

Each configuration starts with a real owned trusted certificate A, invokes production deployment to real certificate B, and then requests a public certificate independently proven absent from every machine store. Actual native bind failure must trigger successful production rollback to B. A further real production deployment restores A. After every transition, raw check-mode/timer DWORDs and existing DefaultFlags must match; independent authenticated TLS must present the expected leaf. A second owned endpoint's complete registry metadata and trusted TLS must remain unchanged. The parent retains exact fixture cleanup ownership on success and failure.

The mandatory host scenario is `windows-iis-client-revocation-policy-preservation`; its bounded `nativeHttpSysClientSettings` proof distinguishes the missing-certificate precondition from actual rollback success. This checks preservation of settings, not a mutual-TLS handshake, client-certificate authentication enforcement or actual CRL/OCSP retrieval. Source and adversarial proof checks are implemented; native Windows execution remains pending.
