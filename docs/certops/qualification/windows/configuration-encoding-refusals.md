# Installed Windows configuration encoding refusals

The supported configuration file is UTF-8 JSON. Windows editors and PowerShell tools can produce a byte-order mark or UTF-16 files instead. This fixture encodes the same valid original operator configuration as UTF-8 with BOM, UTF-16LE with BOM and UTF-16BE with BOM; it does not rewrite user intent or add encoding support.

Offline tests execute the actual production configuration reader against those owned temporary copies, require its specific parse failure and unchanged bytes/state marker, then restore valid UTF-8 and load it successfully. This is reader evidence, not installed-service qualification.

The native source uses the existing owned stopped-service startup path with automatic SCM recovery disabled. Every encoding must yield a fresh real startup parse failure and stopped service while the original registered identity, protected CNG key, HTTP.sys binding and trusted TLS remain unchanged. Exact original configuration restoration, a new owned SYSTEM child and a genuine authenticated heartbeat must precede guard release. The native hook, closed public proof and exact source inventory are mandatory in all ten Windows/key-profile slots. Native Windows execution remains pending. Writes use a retained original file descriptor with pre/post namespace identity checks; identical-byte foreign replacement is refused before mutation. A private original backup and sticky guard remain on unresolved failure. Pin bytes remain identical across repair; the actual production startup may legitimately replace its pin file object.
