# Native helper checks before installer activation

The Windows installer checks the selected service host and AD CS/store-survivor helper before creating or changing installed application/state. It checks the actual staged copies again before either directory rename. Both AMD64 and ARM64 use the same bounded parser; these are public image inspections, never candidate execution.

The parser requires DOS/PE signatures, the selected COFF machine, executable non-DLL characteristics, PE32+ optional headers, bounded header/data-directory/section tables, aligned image/header sizes, nonoverlapping in-file raw sections and virtual sections, and a file-backed executable code entry point. Images are capped at 64 MiB and 96 sections. It rejects reparse paths and holds a read handle that excludes concurrent writing/deletion while reading. This structural validation does not prove Authenticode trust, a signed release, full Windows loader compatibility or correct runtime behavior.

A preexisting staging directory is refused. A newly created stage is bound to its actual filesystem volume/file index using the validated system Node runtime and built-in `fs`, independent of package code. Cleanup and activation recheck that identity. Replaced directories, linked ancestors and linked descendants are preserved rather than recursively removed. Failed stage validation must preserve the old installation; cleanup uncertainty produces an explicit failure and leaves the directory for inspection.

The supporting PowerShell test extracts only the production functions through the parser. Four positive controls read actual compiled service-host/chain images for both architectures. Forty-four image negatives cover missing files, truncated headers/sections, wrong architecture, optional-header magic, entry points, raw overflow/overlap, DLL characteristics and PE offsets. Additional cases prove that a valid source does not excuse a corrupted staged copy and that replaced/linked staging cleanup is refused. No candidate image, installer top-level code, service, registry or certificate operation executes during these checks.

The installed Windows journey separately requires six real installer refusals on its running RSA2048 fixture: missing, truncated and wrong-architecture selected host and selected chain helper. These must preserve the service process identity, configuration, credential, signing pin and unused bootstrap token, without creating swap directories. The existing health rollback case now supplies the genuine selected-architecture chain helper in the service-host slot: it passes structural PE validation but fails the SCM service protocol. This preserves the distinct runtime health-check rollback boundary.

The temporary-filesystem supporting tests have run locally. Actual installed-service refusal and runtime rollback execution remain pending on the protected Windows qualification lanes. The controls do not qualify ARM64 native execution merely because ARM64 image bytes pass inspection.
