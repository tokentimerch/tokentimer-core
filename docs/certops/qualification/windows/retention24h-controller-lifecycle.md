# Disposable native day-long retention lifecycle

The manual main-only prepare workflow provisions one isolated Server 2022 AD CS lab under the approved lab identity. Its actual public issuance and cutover producer freezes a normal four-hour lease and starts one SYSTEM ScheduledTask on the existing member VM. The hosted job does not wait a day, and no permanent lab or self-hosted runner is introduced.

The hosted controller verifies the exact Azure VM, original creation/expiry, candidate, source fingerprints, task XML semantics, actual resident process and independent native custody/TLS observations. It uploads the original four-hour receipt first. Only after downloading that immutable, nonce/attempt-bound GitHub artifact and verifying its digest does it repeat the observations and tag comparison, extend once to the original creation plus 32 hours, and upload a separate handoff receipt. Any failed or cancelled preparation, including either upload failure, invokes the dedicated abort adapter as its final step. It authenticates the exact current run, candidate, attempt and initial random nonce, then verifies deployment/VM creation ownership or the sealed original chain before deleting. A preexisting, replaced or incompletely proven group is preserved; a matching name or purpose tag alone never authorizes deletion. Diagnostic uploads run before that final abort so their failure also invokes cleanup. If abort itself fails, its bounded public orphan receipt is emitted to the persistent workflow log before the local receipt is written, alongside a fixed CI error, and the independent janitor provides subsequent cleanup diagnostics.

Before writing the sealed handoff receipt, the controller deallocates only the exact owned `domain-ca` and `control-plane` VMs. It checks candidate/purpose tags, original deployment resource IDs, VM identities and actual `PowerState/deallocated`; the same member VM must remain running. Failure aborts preparation. The resident collector uses local CNG, IIS and trusted TLS and needs neither remote API nor CA during its window. The member and provisioned storage remain until final deletion.

Hourly short finalizer jobs download both authenticated artifacts, verify the successful owning main/manual run and exact VM/lease, and require the original task to finish. A fresh native observation proves the original process is absent, the VM did not reboot, predecessor certificate/key are gone, replacement custody/TLS remain valid and the genuine production ledger is removed. The resident proof must measure a full day, bounded hourly sweep gaps and a genuine predeadline observation. Qualified reporting happens only after independently verified resource-group absence; incomplete cleanup emits a bounded failure receipt and cannot qualify.

Preparation uses a run-and-attempt-specific concurrency queue with cancellation disabled, so pending protected-environment approval cannot block unattended cleanup. No resources exist before approval. The entire prepare job, including cleanup steps, has a 180-minute limit; the initial four-hour resource lease starts during that actual job. Valid preparation therefore ends before the earliest initial expiry. Finalizer and both independent janitors retain a shared, non-cancelling cleanup queue. Controllers preserve an in-progress owner before expiry and require a successful completed owner with sealed handoff before finalization. Failed or interrupted owners remain subject to independent expiry and immutable hard-deadline cleanup. The adapter uses comparison and readback within these non-overlapping phases; it does not claim an atomic Azure transaction. The [Resource Groups Update API](https://learn.microsoft.com/en-us/rest/api/resources/resource-groups/update?view=rest-resources-2021-04-01) does not document an ETag/If-Match contract used here. External Azure operators are not serialized by GitHub.

The scheduled finalizer can run from a later main commit. Release collection keeps the native candidate unchanged: it independently authenticates the successful finalizer and its five controller-source digests, the original successful prepare run and attempt, and both sealed artifact digests and sealing chronology through GitHub. Downloaded ownership data must match the flat native proof and original source fingerprints. Other candidate campaigns are excluded before parsing their native proofs. Authentication happens before public projection; raw ownership envelopes are not written into collected reports. The candidate-equality rule for all other producer workflows remains unchanged.

The cleanup environment must use a separate least-privilege identity and run unattended, without the lab environment's approval gate. The existing expiry janitor protects initial preparation. The dedicated janitor handles failed owners, immutable receipt expiry and conservative orphan cleanup when uploads are missing. That fallback verifies the exact authenticated owning run, candidate, attempt, Azure VM ownership and deployment creation chronology; it uses the independently authenticated attempt-specific prepare job start after environment approval plus 32 hours rather than trusting mutable expiry tags. It grants no elapsed qualification.

Original creation plus 32 hours is an unextendable authorized lease deadline. GitHub scheduling delays or Azure deletion outages can delay actual resource deletion and billing cutoff. Hourly independent cleanup, bounded teardown polls, explicit absence checks and orphan failure artifacts reduce that risk; they do not create an absolute cloud-cost guarantee.

Each dynamic native observation executes once into a private exclusive public snapshot. Bounded chunk retrieval reads those unchanged bytes; exact file identity, length and hash guard cleanup, and replacements remain preserved. The built-in identity probe removes inherited Node preload/search settings and restores them afterward.

Only bounded public identities, source hashes, task observation facts and sanitized composite reports are uploaded. Domain credentials, agent configuration, private keys, CSRs, raw task XML, raw command output and signed artifact download URLs are excluded. Authenticated GitHub API requests use manual redirects; signed blob downloads receive no GitHub authorization header. ZIP handling reads one exact bounded member in memory and never extracts archive paths.

These adapters and source controls are implemented. Azure provisioning, the actual resident day and native qualification have not run locally; execution remains pending on the protected workflows.
