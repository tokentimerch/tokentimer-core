# Real agent/API/ACME filesystem qualification

The manual `certops-real-acme.yml` workflow runs on trusted `main` only. It uses disposable Linux infrastructure, native Pebble v2.8.0, its DNS challenge server, certbot 4.2.0, migrated PostgreSQL and the real API and agent processes. The fixture endpoints bind to loopback; private keys and bootstrap credentials stay in temporary directories and are excluded from artifacts.

The required journey registers the agent through the API, creates an issuance through the production service under the workspace lock, consumes a signed claim, generates an agent-local key/CSR, obtains a certificate through a real DNS-01 order, deploys it to a filesystem destination and reports evidence through the API. Independent X509 parsing, private-key matching and a TLS handshake confirm the deployed certificate. An explicit twelve-name execution report includes the eleven supporting protocol cases and rejects missing, skipped or failed cases.

After issuance, the real derived renewal profile and automation-enabled management period must exist. Pebble's six-day leaf naturally falls inside the default renewal window. The actual renewal scheduler function selects persisted state and creates an automatic job; the same agent must complete it with new public bytes, matching local key and persisted evidence. The TLS fixture loads the deployed files on each SNI connection, so its observed fingerprint must change to the renewed leaf. This proves scheduler-function selection and filesystem redeployment, with no rewritten expiry or seeded profile.

This lane does not establish Windows/IIS qualification, domain AD CS qualification, a separately running worker daemon or the administrator HTTP issuance route. Issuance creation uses the service directly; registration, claim, evidence and result reporting use the real HTTP protocol. It remains unqualified until its workflow actually runs successfully.

The same real agent process opts into an isolated filesystem discovery directory. OpenSSL creates a separate public certificate with an adjacent key, plus raw private-key, base64-wrapped key, mixed public/private and oversized decoy files. Persisted discovery evidence must contain only the independently checked public fingerprint and expected file path, report adjacent key presence, and contain none of the generated private material. Windows store discovery is disabled for this fixture. These assertions are part of the mandatory journey; their implementation has syntax and focused lint checks, with native Linux execution pending.

To execute locally on a disposable Linux machine, install the pinned native tools, install repository dependencies and start the test Compose stack with migrations. Then run `node scripts/certops-real-acme.js`. The runner refuses occupied fixture ports and terminates its owned Pebble processes in cleanup. The workflow tears down the Compose stack even on failure. Cancellation or runner loss additionally disposes the hosted machine.

The local certbot command disables verification only for the fixture's explicitly loopback ACME endpoint. The independent TLS oracle compares fingerprints without trusting this temporary test CA globally. These settings are confined to this fixture and must not be copied into production configuration.

Pebble command flags follow its [pinned upstream configuration](https://github.com/letsencrypt/pebble/blob/v2.8.0/docker-compose.yml) and [challenge-server entry point](https://github.com/letsencrypt/pebble/blob/v2.8.0/cmd/pebble-challtestsrv/main.go).

After all successful issuance and renewal checks, the Linux journey requires mutation-time lease-loss qualification. Its declared command transparently invokes the real ACME client during positive cases. The final renewal arms a private, run-owned pre-execution barrier, independently observes the actual live command PID and active claim, and force-retires that agent through the public API. Without releasing the barrier, the command must terminate after genuine lease loss; the exact deployed certificate, active private key, trusted served TLS and authoritative DNS must remain unchanged. Both helper sources are bound into every Linux ACME report. Portable command/ownership regressions exercise real benign subprocess trees; the full certificate journey remains unexecuted until hosted qualification runs.
