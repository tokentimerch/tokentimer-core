# Real DNS provider qualification

`certops-dns-provider-qualification.yml` manually qualifies a selected production adapter, or all explicitly enrolled adapters, from the eleven supported production adapters against their actual provider APIs and native TXT resolution: Cloudflare, Route53, Azure DNS, Google Cloud DNS, RFC2136, acme-dns, OVHcloud, Hetzner, Infomaniak, Exoscale, and PowerDNS. The default manual selection is one Cloudflare fixture; an un-enrolled selection fails before credentials or mutation. It runs only on trusted `main`, uses at most two provider jobs concurrently, and serializes each provider with its independent janitor. No external requests or DNS mutations have been executed during implementation; the workflows require protected fixture configuration before full qualification.

Create a qualification environment named `certops-dns-<provider>` and a separate unattended cleanup environment named `certops-dns-cleanup-<provider>` for each adapter you intend to use. Restrict it to trusted `main` and dedicated qualification credentials. Configure the secret `CERTOPS_DNS_CREDENTIALS_JSON` using that adapter's documented credential shape. Configure `CERTOPS_DNS_ZONE` and `CERTOPS_DNS_RESOLVERS_JSON` (a JSON array of native DNS resolver addresses). Both environments must identify the same isolated test zone, reserved label and native resolvers. Give cleanup its own identity limited to observing and deleting the fixture values where the provider permits this separation. Restrict both environments to trusted `main`; the cleanup environment must not require human approval. Qualification may retain its own required reviewers. Use credentials limited to the required DNS operations. The harness checks local credential configuration, not the provider account's complete IAM policy; do not describe that prerequisite as independent proof of least privilege.

After configuring and checking unattended cleanup, set the repository variable `CERTOPS_DNS_ENROLLED_PROVIDERS_JSON` to a JSON array such as `["cloudflare","route53"]`. An absent variable means no providers enrolled. The producer and its child processes reject un-enrolled providers before configuration or mutation. The hourly janitor selects only enrolled providers, so unused adapters do not each start a runner. `all` means all enrolled adapters, never all unconfigured adapters. Remove an adapter from enrollment only after its owned records are drained; exact-receipt recovery remains available after removal. This enrollment is an explicit configuration declaration, not an independent audit of the environment's IAM or approval settings.

The only mutation target is `_acme-challenge.certops-qualification.<zone>`. Reserve that exact label for these tests. Preflight refuses any existing non-fixture TXT value. For acme-dns, configure a dedicated account and this exact label's CNAME to its assigned domain; a production ACME account must not share the fixture. Choose resolvers that can independently observe the selected zone and CNAME, including an appropriately reachable authoritative/test resolver for private RFC2136 or PowerDNS environments. Missing credentials, unreachable resolvers, failed API operations, and missing reports fail qualification rather than silently opting out.

Four mandatory cases create fresh challenge values, retain both concurrently submitted values, clean the first without deleting the second, and clean all owned values. Two actual Node processes submit their values concurrently through the production solver and its normal shared-host file locks. They perform real authentication and DNS operations with the shipped retry behavior. A separate native Node DNS resolver observes actual TXT records with bounded propagation waits. No provider response, socket, resolver, or HTTP transport is replaced with a fixture. Reports identify the actual adapter and classify this as integration evidence, not a complete certificate issuance journey.

Every value carries a reserved prefix, creation timestamp, and random identifier. An atomic local receipt is written before each potentially uncertain API mutation. The workflow's unconditional recovery step retries cleanup of those exact values after a failed test. The separate hourly `certops-dns-fixture-janitor.yml` observes the reserved label and removes only valid fixture values older than two hours. It preserves other values, uses the separate unattended cleanup environment and serializes with qualification through the same per-provider concurrency group. It never shares qualification's approval-gated environment.

acme-dns has no deletion operation: it deliberately keeps two rotating TXT slots. Its mandatory cleanup cases verify the documented no-op semantics and coexistence, and its report explicitly says `not-applicable-two-slot-provider`. The janitor does not schedule an acme-dns runner because there is no applicable deletion operation. Enrollment is still explicit for its qualification run. Neither the test nor the janitor claims deletion or account removal. The dedicated existing fixture account retains only harmless qualification values until later updates rotate them out.

Credentials exist only in the protected process environment and solver memory. They are never written into receipts, command arguments, logs, or uploaded reports. Provider bodies and errors are withheld. Uploaded artifacts contain only sanitized named outcomes; raw resolver values and receipts are excluded. The runner requires GitHub-hosted provenance and `CERTOPS_DNS_DEDICATED_FIXTURE=1` before mutation.

These workflows do not qualify CA issuance, full account/EAB behavior, every provider pagination/auth/error branch, network interruption after a committed provider mutation, or multiple hosts modifying the same RRset. Those remain separate scenarios. Azure DNS tests use an existing dedicated DNS fixture; they do not provision a Windows or Azure VM lab.
