# Real DNS-hook routing qualification

The manual `certops-dns-routing-qualification.yml` runs the candidate production `certops-dns-hook` as separate native Node processes on disposable Ubuntu 24.04. It builds pinned `pebble-challtestsrv` 2.8 and uses its real loopback DNS management interface plus independent native TXT queries. It does not contact an external provider or certificate authority.

Seven mandatory scenarios cover longest child-zone mapping, policy-denied parent provider, dot-boundary suffix matching, zone policy refusal, actual propagation failure after a successful TXT mutation, owned cleanup, and [two independently owned configured resolver views](dns-resolver-views.md). The denied provider's credentials file is deliberately absent: refusal must occur before credentials/provider work. The propagation fault points only the hook's resolver to a confirmed unused local port; an independent live resolver must still see the genuine TXT write. The new Linux-only case requires actual pidfd support and checks all/quorum disagreement and recovery without substituting answers. Cleanup calls the production provider, independently checks value absence, terminates the owned DNS servers, proves management/DNS ports no longer answer, and removes protected temporary configuration only after ownership and cleanup are verified.

Focused execution passed all six cases on the actual local Windows host, followed by strict source-bound report verification. Product-native credentials ACL enforcement refused the initial inherited ACL fixture; using the production restrictive-permissions helper corrected the fixture. This is supporting native hook integration evidence, classified as a local worktree baseline. It cannot qualify the mandatory hosted Ubuntu slot. The hosted workflow has not run; full CI remains pending.

No DNS replies, platform APIs or provider outcomes are replaced. Private fixture configuration stays in a restrictive temporary directory. Reports contain bounded named evidence and measured environment/source identity, without copied command output or configuration. This covers routing/policy/propagation, separately from external provider authentication, pagination, rate limits and real CA issuance qualification.
