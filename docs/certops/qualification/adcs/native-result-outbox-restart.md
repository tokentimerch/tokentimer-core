# AD CS native success with deferred result delivery

The comprehensive root and hierarchy AD CS suites require
`adcs-real-native-success-result-outbox-scm-restart`. It uses the existing
disposable SYSTEM member and issuing CA. No additional VM or preflight is
created. These remain explicit manual domain campaigns with the repository lab
opt-in; this case does not add Azure to the standard hosted profile.

An owned loopback transport forwards the original agent bytes to the original
HTTPS API, verifying its original certificate and hostname. Claim admission is
held until the public enrollment's actual job is registered. Evidence continues
to reach the real API, while only the selected job's result receives HTTP 503.
The installed agent must genuinely issue and install a fresh AD CS leaf and
nonexportable machine key, with trusted SNI TLS and matching IIS/HTTP.sys store,
hash and settings, before the successful durable outbox entry can qualify.

The fixture observes the actual persisted attempt count and `nextRetryAt`;
neither is edited. It stops the exact qualification-created service only after
a read-only observer retains the original host, Node and observed descendant
handles. Ordinary SCM stop must produce natural zero exits and complete handle
drainage. The original protected configuration file stays open by identity;
credential and signing-pin bytes, identities and DACLs must remain unchanged.

The restarted agent uses the production retry loop and its actual deadline.
The original job must finish with the same claim and attempt, one consumed result
nonce and claim-bound leaf evidence. Its journal, CSR/key/leaf, independent
native CA RequestId and total request count stay unchanged. Immediate issued
responses may omit their reported RequestId; every ID actually reported must
match the independently observed CA row.

A second ordinary stop restores the exact original configuration bytes through
the retained original file handle. A fresh authenticated original-API observation,
native custody and trusted TLS precede closing the gateway and ownership guards.
An uncertain stop, changed file/ACL, unknown result or live resource preserves
the entire fixture before parent service, key, site or database cleanup.

`nativeAdcsResultOutbox` is a closed public projection: IDs, request counts,
fingerprints, recorded retry timing and bounded execution flags. It contains no
credentials, native paths, container names or raw outbox contents. This is source
implementation with supporting transport/filesystem/contract checks; native lab
execution remains pending. It does not qualify atomic ownership of future
process descendants, a background renewal timer, every retry duration, OS reboot
or power loss.
