# Native CA-issued unauthorized SAN refusal

This mandatory root/hierarchy source scenario is connected to the parent,
suite inventory, release matrix and strict report verification. It has not run
against a disposable forest.

The control is the genuine installed certificate on the pending-cancel fixture's
site, established by the preceding successful installation-retry/CA-outage
journey using the same issuer and pending template. The helper finds exactly one
registered installed journal matching the independently served leaf, rather than
assuming the original cancelled enrollment installed anything.

A new public enrollment creates a real pending request. The officer fixture
checks the exact RequestId, run-owned CN, machine requester, pending disposition,
template OID and SHA256 of the complete actual public CSR DER read independently
from the CA database. It then replaces only SAN extension `2.5.29.17` with one
literal, distinct DNS name in the same disposable run namespace. No policy,
template, requester, key or CA ACL changes occur. Actual CA approval and issuance
follow; no certificate or response is fabricated.

Independent inspection requires the expected CA signature, unchanged request,
original CN, original CSR SPKI and template, and exactly the unauthorized DNS
SAN. The installed agent receives the genuine signed production continuation.
It must report `rejected_invalid` / `ADCS_CERTIFICATE_INVALID`, accept no copy in
My or WebHosting, preserve the predecessor's exact IIS binding, trusted TLS leaf
and protected native CNG identity, and leave the subject's CA request count
unchanged. Production terminal cleanup must remove the exact unaccepted key;
the rejected journal and original request/CSR identity remain observable. The
officer finally revokes the actual issued faulty request.

Parent integration requires `registerOwnedUnacceptedEnrollment({certificateId,
domain})` **before** the public POST. It returns a receipt with `enrollmentIds`;
the helper appends the actual returned ID immediately. The parent must stop and
drain its exact service before independent cleanup, refuse unknown accepted
associations, confirm each exact owned key absent and preserve all local state
on any unresolved cleanup. The parent implements this registry and checks every
registered target with the production machine-wide public key-survivor guard
before broad predecessor certificate removal. Any unknown accepted association,
untracked dispatch, active job or key cleanup failure prevents later broad
certificate deletion, public fixture cleanup and local state removal. Historical
`awaiting_issuer` jobs are terminal for their attempt; a current pending enrollment
still refuses cleanup.

The local proof/adversary and source-order checks validate supporting contracts
only. Native CA schema availability, issuance behavior and full end-to-end
refusal remain pending protected forest execution.

The public SAN file keeps an original file-ID/hash receipt and retained parent
identity. A read-only no-delete-sharing handle permits the actual `certutil`
reader; cleanup then reacquires exclusive deletion access and verifies the
original identity/hash before deleting by handle. Any replacement preserves the
file and its public owner guard. Benign temporary-file controls exercised actual
`certutil -hashfile` compatibility, replacement refusal during reading, successful
exact cleanup and preservation of an identical-byte foreign replacement. Those
controls perform no CA, certificate-store, key or service operations.
The selective inexpensive Windows CI lane runs them when either exact script
changes; they never qualify the AD CS native scenario.
