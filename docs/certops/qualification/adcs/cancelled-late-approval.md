# Late approval after cancellation and successor installation

This source reuses the comprehensive native suite's publicly cancelled pending
request and the distinct real installation that recovery subsequently completes
on the same owned IIS endpoint. It adds no enrollment, preflight or CA submit.

Before any officer action, the actual CA row must match the original RequestId,
requester, template, public CSR bytes and SPKI. The original public cancellation
audit, terminal cleanup jobs, cancelled journal and absent machine key are
independently required. The currently served trusted leaf must match one owned
installed journal, a succeeded claim-bound job and persisted evidence. Native
CNG possession, provider and nonexportability, IIS SNI and HTTP.sys must agree.

The officer then approves the original cancelled request. Its actual issued
leaf must have the original CSR key and names, correct template and CA signature.
The default-clock continuation scheduler creates no revival; a separate overdue
eligibility control also creates none. Public installation retry is refused.
Original and successor database rows, jobs, journals, evidence, protected native
custody and trusted TLS must remain unchanged. The late leaf is absent from every
machine store and the cancelled key remains physically absent.

Cleanup re-reads authoritative CSR/requester/template ownership and issued DER
before revoking only the unused late issuance. The CA request count stays fixed;
successor custody and TLS are checked again. Any unresolved step keeps a parent
cleanup guard so native material and durable ownership are preserved.

The successor has a distinct certificate identity. This is protection of a
superseding deployment on the same endpoint, not a claim of same-certificate
renewal. No native clock, database date, journal or agent result is manufactured.
Supporting source tests are separate from protected native execution, which is
pending. The scenario and closed measured proof are mandatory in both comprehensive
root-domain and hierarchy suites; strict collection and release validation bind
the current native, API and harness source fingerprints.
