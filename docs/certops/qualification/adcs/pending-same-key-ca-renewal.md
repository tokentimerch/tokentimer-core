# Same-key CA renewal while a real enrollment is pending

This root-CA-only source reuses an already installed capacity target and its exact My-store cleanup receipt. It first verifies the currently served trusted leaf against an actual installed journal and original accepted-container record; it does not blindly treat the first capacity enrollment as the current certificate.

A new public enrollment uses the existing confirmed manager-pending issuer. A durable receipt guard is set before public dispatch, and the returned enrollment UUID is registered before later assertions. Actual pending CA disposition9, signed awaiting-issuer job, CSR bytes/SPKI, snapshot and protected machine CNG signature are observed before the existing scenario's single CA same-key renewal and preflight callback runs. No extra selector, CA renewal or preflight is added.

The CA certificate set must grow while every actual public certificate retains the confirmed key. The pending issuer version/confirmation, exact CA request count/RequestId, CSR/key and predecessor CNG/IIS/trusted TLS remain unchanged, without reconfirmation. Only then does the real officer approve that same request. The production signed continuation must retrieve, validate and install its real CSR-matching leaf onto the original pending key, with native My/IIS/SNI and trusted TLS observations and claim-bound verification evidence. The predecessor's protected key and original acceptance record remain intact.

Continuation eligibility uses the existing supported scheduler-now input at the persisted poll time. CA/native clocks, journals, request IDs and results are not rewritten. This is not a background worker-interval test, signed CMC renewal, CA key rotation or subordinate/offline-parent renewal. The existing later new-issuance control remains separate.

Any unresolved or accepted failure leaves the receipt guard set, preserving public certificates, registered keys and local recovery state. Successful qualification releases it only after all native identity/evidence checks. The existing parent owns exact stopped-service store/key cleanup and disposable-lab teardown. Two mandatory scenarios and strict capacity-bound public proof are wired into all nine root-domain release cells, with actual critical source digests. Hierarchy and elapsed-only lanes exclude this root CA mutation. Source/proof checks are implemented; native forest execution remains pending.
