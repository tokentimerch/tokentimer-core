# AD CS renewal in WebHosting

The native helper exercises a separate owned IIS SNI site through two public enrollment requests for the same certificate identity. The installed SYSTEM agent must accept both RSA keys into `LocalMachine/WebHosting`, replace the binding with a fresh key and certificate, and publish its actual discovery observations. Independent CA request queries, protected native key association, HTTP.sys and IIS certificate-store coordinates, and trusted TLS must agree.

The helper requires an existing confirmed short-lived RSA issuer and its independently measured authority, an isolated exact allowlisted domain and site, and installed discovery configured for both `My` and `WebHosting`. It registers a store-qualified cleanup record before dispatch. The parent captures the exact SYSTEM service path, configured state directory and process creation tree before stopping and deleting the service. Public store cleanup requires every captured process and any late child to be absent. It then removes only public certificate entries whose exact key container, certificate identity, accepted store and thumbprint match durable production receipts, before removing the exact enrollment key containers. A failed job may leave an accepted public certificate before a thumbprint is observed: cleanup must reconcile the registered enrollment key identities against the exact registered store/domain and refuse foreign replacements.

The second check compares production discovery with persisted inventory, verifies both immutable acceptance receipts still name `WebHosting`, and reads the unmodified predecessor retention row with the same store, original key and replacement thumbprint. This validates store coordinates and predecessor preservation. It does not qualify expiry-based deletion, additional stores, a scheduler interval, or signed renewal requests.

The supporting tests validate only the bounded proof and source inventory. Actual Windows, domain, CA, CNG, IIS and installed-agent execution remains pending the protected disposable native workflow. The parent producer now invokes both cases before the CA rollover controls and requires their scenario IDs. Strict report inventory and native execution must still include their proof before this source supplies any qualification result. Unresolved public cleanup blocks key deletion for the registered enrollments and preserves their state directory.
