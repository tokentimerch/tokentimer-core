# Exact local CA and template refusal

The protected AD CS journey includes three additional agent-local enrollment-rule boundaries: a different CA host, a different CA authority on the same host, and a different template on the same exact CA. Each changes one dimension while retaining the owned DNS name and RSA permission. These are distinct configured identities, never case, trailing-dot or DNS aliases. Existing native controls already cover missing constraints, DNS suffix boundaries, algorithms, permission cross-products, additional SANs and policy tightening during pending issuance.

The controller admits a genuine signed job against its existing confirmed issuer. Only the installed agent's local rules change. The agent must refuse before allocating a CA request or generating a new key. An independent native CA checkpoint must remain identical; a failed checkpoint is an error, never evidence of absence. The exact enrollment key must be absent, no enrollment journal or issuance receipt may exist, and the persisted request ID must remain null. The prior certificate DER, CNG provider/container/machine/export/usage metadata and trusted served TLS certificate must remain unchanged.

Configuration replacement waits for the owned service to stop. Restart recovery requires a fresh authenticated heartbeat after a database marker recorded while stopped and the exact original credential bytes. Every case restores the original configuration bytes and checks custody, TLS and CA state again before emitting its bounded proof. A restoration failure fails qualification. Native key paths, certificate DER, credentials and command output stay out of reports.

`nativeLocalRulePairs` contains exactly the three case IDs and eight boolean facts, validated by `verifyPairProof` in the existing local-rules helper. `scripts/certops-adcs-local-pairs.test.js` checks the real policy matcher and adverse proof shapes without running a service or touching certificates. These offline checks do not establish native qualification; actual execution remains pending on the protected disposable root and hierarchy lanes. No additional preflight calls or primary-dispatch budget are needed.
