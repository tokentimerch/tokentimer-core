# Terminal certificate renewal admission

`terminal-renewal-admission-api` verifies that public manual and bulk renewal cannot revive an operator-retired identity. Seven mandatory scenarios use real authenticated API requests, PostgreSQL, public certificate imports and independently trusted loopback TLS. Complete linked agent-local renewal profiles/key mode are explicit SQL prerequisites. No jobs, certificate expiry or observations are seeded.

The active positive control creates a real manual renewal awaiting approval for each of two certificates, then publicly rejects those jobs. One identity is publicly revoked and the other decommissioned. A separate transaction holds only those owned managed-certificate rows with `FOR NO KEY UPDATE` during retirement. This changes no fixture data: it deterministically exercises the production path that skips a locked source cache while committing the authoritative identity lifecycle. The lock always rolls back and releases before later checks and cleanup.

Manual renewal must return `409 CERTOPS_CERTIFICATE_NOT_RENEWABLE` and bulk renewal must return the same per-item code while the imported source cache remains stale. Exact managed-certificate/profile, job, outbox, identity, token and audit snapshots must remain unchanged after each refusal. The active controls prove that incomplete profiles or unusable custody cannot explain the refusal.

An independent TLS client then trusts only the corresponding owned certificate and verifies its exact fingerprint before public domain scanning records factual use. The public identity and token remain terminal. This new observation need not update the separate imported source cache; manual and bulk refusal are verified again afterward. Cleanup removes only the fixture workspace, temporary private files and owned TLS listeners.

The shared materializer checks authoritative identity lifecycle before profile construction, as well as the source's cached status. Focused local execution passed all seven scenarios and reproduced HTTP 201 with the previous cache-only guard. Reports bind the current test, API fixture, retirement service, jobs service and route sources. These are admission assertions: no CA issuance, native installation, hosted matrix or full release qualification is established.
