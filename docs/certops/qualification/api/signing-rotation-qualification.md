# Native signing key rotation qualification

The manual `certops-signing-rotation-qualification.yml` workflow runs nine mandatory scenarios against a fresh disposable API and PostgreSQL stack on Ubuntu 24.04. It starts two unmodified native Node agents, observes actual signed public noop jobs, and invokes the production operator CLI for status, begin and completion. A stopped agent prevents completion until its actual heartbeat adopts and acknowledges the new pin. Restarted agents must retain credentials and execute a new-key signed job exactly once.

This suite changes deployment-global signing state. It requires an explicit separate-stack opt-in and refuses a database containing any agent or signing key before registration. Never point it at a shared development, qualification or production database. Local focused execution uses a separately owned database and API; the ordinary API qualification runner deliberately excludes this suite.

All nine scenarios passed a focused execution using actual Linux Node 24 agent processes and operator CLI against a separately owned API/PostgreSQL fixture. Its report proves operator CLI and native pin adoption, rather than certificate issuance, Windows service recovery or every signing-protocol permutation. It never uses forced completion or fabricates acknowledgements. Private credential and pin files remain in owned temporary directories and are removed after agents stop. Workspace fixtures are removed; deployment-global signing keys and operator audit records are destroyed with the entire disposable database in the workflow's unconditional teardown.
