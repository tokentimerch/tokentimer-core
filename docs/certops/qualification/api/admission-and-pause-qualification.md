# Issuance admission and workspace pause qualification

Two mandatory disposable API/PostgreSQL suites exercise public provisioning and workspace governance. They use real authenticated sessions, registered protocol agents, persisted attempts and audit records. They do not contact an issuer or mutate a native certificate store.

`first-issuance-admission-api` creates first issuance through the public jobs endpoint and independently checks the provisioning certificate and its active management period. An agent lacking claim-bound evidence support cannot receive the job. Wrong DNS providers, target names and command profiles cannot consume an attempt. Stopping the management period cancels its pending job; restoring agent declarations cannot resurrect it. A separate eligible request produces exactly one signed dispatch, whose signature and agent/job/certificate/claim bindings are checked independently.

`pause-ingestion-api` claims an owned noop job before pausing and leaves another pending. Public settings changes produce one audit event per state transition, including the supplied reason; repeating the same pause does not duplicate its event. Paused claims receive `409 CERTOPS_WORKSPACE_PAUSED`, pending attempts remain untouched, and new noop and issuance requests are refused without provisioning a certificate. Heartbeats, claim-bound policy evidence and the already-owned noop result remain accepted. Resuming records its audit event and makes the untouched pending job claimable once.

The registered agent fixture reports noop results and policy observations directly over the actual protocol. A separate paused discovery case generates a real public certificate with OpenSSL, keeps its private key outside the scanned directory, and runs the production filesystem collector. Authenticated ingestion must persist the independently parsed fingerprint, a confirmed-present stored-copy location and exactly one observation slot. Every existing job status, claim and attempt remains unchanged, the original pause audit remains unique and new claims still receive `409`. This proves passive discovery during pause; it does not claim native certificate-store, service or issuer execution.

Heartbeat declarations distinguish omission from removal for `supportedOperations`, `declaredCapabilities` and `declaredCommandProfileNames`: omitted fields preserve their corresponding stored values, an explicit empty array clears them, and a nonempty array replaces them. The native agent publishes its current command-profile names on each heartbeat; command arguments remain local. Target selectors retain their existing nonempty replacement behavior. Upgrade the server before agents that send newly accepted heartbeat fields, because unknown fields are rejected by the protocol schema.

The central API qualification runner invokes both suites explicitly: issuance admission has six mandatory scenarios and pause ingestion has seven. Pause ingestion explicitly checks its OpenSSL prerequisite and binds the collector, registered-agent helper and agent entry point in addition to the producer source. Missing prerequisites, skipped mandatory cases, stale source hashes or missing reports fail strict verification. All seven pause cases passed locally against actual API/PostgreSQL with current source fingerprints and owned cleanup. Hosted workflow and release qualification remain pending until the final candidate is tested in CI.

The separate `derivation-failure-api` suite imports independently generated public certificate material, then explicitly seeds historical active status as a prerequisite. It calls the production derivation service against PostgreSQL with historical issuance payloads missing the CA endpoint, local command profile, DNS provider, zone or certificate destination. Each refusal must identify the missing field, preserve the active certificate and exact public fingerprint, and create no profile. A complete control payload must derive successfully. Public detail remains noneligible for renewal, and no job is fabricated. This six-case suite passed locally; it does not demonstrate genuine issuer completion, host custody, or promotion through the full reconciliation path.
