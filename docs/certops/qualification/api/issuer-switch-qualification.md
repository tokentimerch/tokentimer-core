# Public renewal issuer switch policy

The `profile-issuer-switch-api` suite contains six mandatory cases executed through the real authenticated API and PostgreSQL database. A valid confirmed AD CS issuer reassignment preserves the immutable deployment/key policy and writes its audit event. Unconfirmed, foreign-workspace and incomplete reverse-to-ACME switches atomically preserve every profile field and audit count. Repeating the same issuer produces the documented no-change response without jobs or additional audit writes.

All six cases passed focused execution, independent strict report verification and lint. Confirmed/unconfirmed issuer rows are explicitly seeded admission-policy prerequisites. This supporting integration evidence does not prove native CA confirmation, certificate issuance, host deployment or a full ACME/AD CS renewal migration. Those journeys remain in the qualification catalog. The central API runner executes this suite against its disposable stack; hosted/full CI remains pending. The native confirmed AD CS switch and production scheduler renewal is specified in [Native AD CS issuer reassignment](../adcs/native-issuer-reassignment.md) and remains pending.
