# Native Linux certificate dry-run

The `native-agent-api` suite includes four certificate-operation scenarios in addition to its existing signed noop dry-run. The fixture runs the unmodified Linux Node agent against the actual API/PostgreSQL stack. Owned CA-signed certificates, restrictive custody files, a real TLS listener and independent command/gateway counters distinguish a useful dry-run from an unconfigured path that could never mutate anything.

The generic public job route intentionally does not expose a selectable execution mode. These scenarios explicitly call the production `createCertificateJob` service with `mode: "dry_run"`; the normal public certificate import, real signing, native claim/lease/result handling and persisted evidence remain in use. Jobs, dispatches, nonces, successful outcomes and evidence rows are not fabricated.

- `native-agent-certificate-deploy-dry-run` requires the actual signed deploy operation to finish as `dry_run_complete` with three authenticated plan steps. The exact owned file inventory, custody key bytes/modes/inodes, deployed certificate and independently trusted served leaf remain unchanged. Neither validate nor reload runs.
- `native-agent-certificate-renew-dry-run` requires the actual signed renew operation to finish as `dry_run_complete` with six authenticated plan steps. The request includes key rotation, an allowlisted external ACME command, CA endpoint, DNS provider/zone and reload command references. No staging artifact, key change, deployment, child command or gateway request may occur.
- `native-agent-certificate-real-deploy-control` uses real execution mode against the same target. Production atomic deployment installs a distinct valid certificate, actual allowlisted validate/reload children execute, and the real TLS listener presents the independently expected replacement leaf. This demonstrates that the dry-run side-effect oracles are sensitive.
- `native-agent-certificate-command-sentinel-control` invokes the real renewal adapter with an allowlisted fixture command. That child contacts owned HTTP CA/DNS sentinels, then deliberately exits unsuccessfully before issuance. The deployed certificate and served TLS remain unchanged. These HTTP sentinels are explicit fixture controls, not an ACME server or DNS provider; this case does not qualify successful issuance or propagation.

The fixture keeps generated private keys local and suppresses OpenSSL output. Its report contains bounded counts and boolean proof fields, never key material, command output, certificate bodies or raw database rows. Exact configuration and credential/signing-pin identity must survive restoration. Cleanup stops owned agent children, closes both owned listeners and removes only the exact run-owned fixture directory; the parent independently cleans its remaining API identities and process state.

Three supporting tests verify that every proof field and exact control count is required, that additional private fields and incorrect qualification scope are rejected, and that the file oracle detects changed key bytes and new staging artifacts. Supporting tests do not replace native execution. Local container reports retain local baseline provenance and cannot promote themselves into hosted release evidence.
