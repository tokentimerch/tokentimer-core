# Certificate-producing integration source qualification

The committed [source inventory](integration-source-inventory.json) names the six certificate source kinds produced by AWS ACM, Azure Key Vault certificates, Google Certificate Manager, Google Compute SSL certificates, and Vault KV/PKI. Run `node scripts/certops-integration-source-inventory.js` to reject missing, duplicate or stale scanner mappings. Static source metadata cannot qualify a live provider.

`tests/e2e/certops-integration-sources-e2e.test.js` runs twenty-one mandatory supporting integration scenarios against a disposable authenticated API and PostgreSQL stack. Production scan persistence records exact source kind/object identities. Actual HTTP import binds these records to inventory tokens; repeated imports update the same tokens. Viewer imports and foreign workspace imports are refused. Forged client instance, owner and dimension fields cannot replace server-persisted provenance. Real scanner HTTP 401, 429, 503 and malformed successful Certificate Manager/Compute response scopes are persisted as incomplete; authenticated cleanup preserves the previous certificate token. A newer real scan observation fences an older completed empty scan. A subsequent complete empty scan deletes only its exact source kind, and replay cannot delete again. An actual configured worker bearer cannot use unfenced legacy import cleanup to delete inventory or consume the scan. This tests the server worker-principal boundary, not an auto-sync worker process or scheduler. Cleanup removes only fixture-owned workspaces and users.

Production AWS, Azure, GCP and Vault scanners run intact against SDK/HTTP transport fixtures in an isolated test process. Azure and Vault parse a freshly generated public X509 certificate; Vault KV also receives an owned private key fixture, whose bytes must not appear in normalized output. Transports and module cache are restored before real API requests. These scenarios do not contact cloud/Vault servers, issue certificates through a provider, prove private key custody, or establish a CertOps management period. Live provider permissions and pagination, auto-sync worker execution, and other provider-specific absence/reconciliation variants remain additional coverage requirements. The scanner unit suite also verifies pagination, upstream failures, unreachable Compute regions and ACM permission denial. A certificate inventory token is not evidence of deployment or issuance.

The suite is included in the central API qualification runner and mandatory release matrix. The local twenty-one-scenario execution passed with independently verified strict evidence; its local worktree provenance cannot satisfy the hosted Linux release slot. Full hosted qualification is pending.

For focused execution set `CERTOPS_CSR_DISPOSABLE_STACK=1`, `CERTOPS_CSR_API_URL`, the disposable PostgreSQL `DB_*` variables, `CERTOPS_API_WORKER_FIXTURE_KEY` matching the disposable API worker/session key, `CERTOPS_E2E_REQUIRED=1`, and `CERTOPS_INTEGRATION_SOURCES_REPORT`. Run `node --test tests/e2e/certops-integration-sources-e2e.test.js`, then independently verify the report with `node scripts/certops-qualification-report.js <report.json>`.
