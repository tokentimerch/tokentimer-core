# Multi-target filesystem deployment qualification

`multi-target-deploy-api` runs the production deployment coordinator against actual temporary filesystem destinations and independently generated end-entity certificates and keys. A registered protocol agent owns a genuine noop claim. The coordinator's step evidence travels through authenticated API ingestion under that claim; the fixture adapter assigns evidence identifiers and does not replace filesystem operations or return fabricated API responses.

Eight mandatory scenarios check the owned context, deployment to both destinations, idempotent permissions repair, all-target preflight refusal, reverse rollback after a second destination fails, removal of an earlier first installation, explicit uncertain rollback after deliberate backup loss, and cleanup. Public certificate fingerprints and local key matches are read independently from the destination files. POSIX key modes must be `0600`; Windows keys must have protected ACLs permitting only the service's trusted identities. An actual Everyone read grant is added to run-owned Windows keys and must be removed by byte-identical replay without changing bytes or modification times.

The second-destination fault uses a genuine existing directory where a certificate file must be written. The original files at the earlier destination must be restored byte-for-byte. The uncertainty case deliberately deletes the fixture's retained predecessor backups immediately before the later destination fails. The actual coordinator must return `orphaned_unknown_effect` and the `multi_target_rollback_uncertain` reconciliation reason, rather than claim restoration. This is controlled local artifact loss, not a simulated process crash or filesystem response.

The test uses temporary native files and actual HTTP/PostgreSQL evidence ingestion. It does not exercise public deploy admission, installed-agent dispatch, consuming daemon reload, served TLS, CA contact, or certificate management promotion. Those remain separate qualification journeys. Private material and private-file digests are excluded from reports; source hashes identify the executed test. Cleanup independently removes the fixture workspace and the checked temporary directory even after failure.

The private-file implementation enforces the existing Windows ACL helper on empty staging files before writing private bytes. The same protection applies to new key backups, rollback writes and agent custody promotion. Paired idempotent replay repairs the existing key ACL while preserving file content. A focused regression independently inspects the staging ACL while the file is still empty. The Windows PowerShell ACL oracle clears inherited PowerShell module-path overrides so it loads its own security module.

Focused local execution passed on Windows and in an isolated pinned Debian 12 container. The complete focused deployment regressions passed on Linux (56 tests without skips); Windows passed 54 with two existing POSIX-only skips. Hosted filesystem workflows remain pending; local results do not qualify a committed release artifact.
